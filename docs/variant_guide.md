# Техническое руководство: экран физической культуры в проекте Eltech

## 1. Назначение руководства

Данное руководство описывает логику и этапы реализации экрана физической культуры для мобильного приложения Eltech. Экран предназначен для отображения прогресса студента по физкультуре: посещений, накопленных баллов и статуса выполнения требований.

Руководство подготовлено в рамках вариативной части проектной практики и связано с личным вкладом:

**Студент:** Карпов Александр Владимирович  
**Группа:** 251-371  
**Направление:** экран физической культуры

## 2. Исходные файлы

В папке `src/` размещены Kotlin-файлы, связанные с вариативной частью:

| Файл | Назначение |
| --- | --- |
| `src/PhysicalScreen.kt` | Основной экран физической культуры |
| `src/GroupJournalScreen.kt` | Экран журнала группы |
| `src/HomeScreen.kt` | Главный экран сервисов с переходом к физической культуре |

Эти файлы относятся к UI-слою приложения Eltech и написаны с использованием Compose Multiplatform.

## 3. Цель модуля

Цель экрана физической культуры - дать студенту быстрый и понятный способ проверить текущий прогресс по дисциплине без необходимости искать данные в веб-версии личного кабинета.

Экран должен отвечать на три основных вопроса:

1. Сколько баллов уже набрано?
2. Сколько занятий посещено?
3. Что ещё нужно выполнить для закрытия требований?

## 4. Место экрана в архитектуре Eltech

Проект Eltech использует подход Kotlin Multiplatform. Это означает, что часть бизнес-логики может быть вынесена в общий модуль, а интерфейсные элементы реализуются на уровне мобильного клиента.

Упрощённая схема:

```text
UI экран физкультуры
        |
ViewModel / Presenter
        |
Use Case получения прогресса
        |
SDK_Eltech
        |
Личный кабинет / API университета
```

## 5. Основные данные экрана

Для работы экрана требуется модель прогресса студента.

```kotlin
data class PhysicalEducationProgress(
    val studentId: String,
    val score: Int,
    val requiredScore: Int,
    val attendedLessons: Int,
    val requiredLessons: Int,
    val status: ProgressStatus
)

enum class ProgressStatus {
    COMPLETED,
    IN_PROGRESS,
    NEED_ATTENTION
}
```

Описание полей:

| Поле | Назначение |
| --- | --- |
| `studentId` | Идентификатор студента |
| `score` | Текущее количество баллов |
| `requiredScore` | Количество баллов, необходимое для выполнения требований |
| `attendedLessons` | Количество посещённых занятий |
| `requiredLessons` | Минимальное или плановое количество занятий |
| `status` | Итоговый статус прогресса |

## 6. Практическая реализация экрана

Основной экран реализован в файле `src/PhysicalScreen.kt`. В нём используется composable-функция `PhysicalScreen`, которая хранит состояние выбранной вкладки и состояние открытия журнала группы.

Фрагмент структуры:

```kotlin
@Composable
fun PhysicalScreen(
    onJournalStateChange: (Boolean) -> Unit = {}
) {
    var selectedTab by remember { mutableStateOf(0) }
    var openJournal by remember { mutableStateOf(false) }

    if (openJournal) {
        GroupJournalScreen(
            onBack = {
                openJournal = false
                onJournalStateChange(false)
            }
        )
        return
    }
}
```

Экран состоит из нескольких самостоятельных composable-блоков:

* `HeaderBlock()` - карточка с данными студента;
* `JournalCard()` - переход в журнал группы;
* `Tabs()` - переключение между посещениями, нормативами и дополнительными баллами;
* `VisitCard()` - карточка посещения;
* `Placeholder()` - состояние для разделов без данных.

## 7. Экран журнала группы

Файл `src/GroupJournalScreen.kt` содержит экран журнала группы. Он отображает список студентов и показатели по каждому: посещения, баллы, LMS и группу здоровья.

Основная модель:

```kotlin
data class Student(
    val name: String,
    val visits: Int,
    val points: Int,
    val lms: Int,
    val group: String
)
```

Экран журнала открывается из карточки `JournalCard()` и закрывается через callback `onBack`.

## 8. Интеграция в главный экран

Файл `src/HomeScreen.kt` показывает, как экран физической культуры встроен в общий раздел сервисов приложения. Пользователь открывает раздел «Сервисы», выбирает пункт «Физическая культура», после чего отображается `PhysicalScreen`.

## 9. Use Case получения прогресса

В доменном слое можно выделить отдельный сценарий использования.

```kotlin
class GetPhysicalEducationProgressUseCase(
    private val repository: PhysicalEducationRepository
) {
    suspend operator fun invoke(studentId: String): PhysicalEducationProgress {
        return repository.getProgress(studentId)
    }
}
```

Такой подход отделяет интерфейс от источника данных. Если в будущем изменится API личного кабинета, UI-экран не потребуется переписывать полностью.

## 10. Состояния интерфейса

Экран должен учитывать несколько состояний:

| Состояние | Описание |
| --- | --- |
| Загрузка | Данные запрашиваются из SDK или кэша |
| Успешная загрузка | Отображаются баллы, посещения и статус |
| Ошибка | Пользователь видит сообщение о невозможности загрузить данные |
| Нет данных | Отображается нейтральное состояние, если информация отсутствует |

Пример модели состояния:

```kotlin
sealed interface PhysicalEducationUiState {
    data object Loading : PhysicalEducationUiState
    data class Content(
        val progress: PhysicalEducationProgress
    ) : PhysicalEducationUiState
    data class Error(
        val message: String
    ) : PhysicalEducationUiState
    data object Empty : PhysicalEducationUiState
}
```

## 11. Логика отображения прогресса

Для удобства пользователя прогресс можно отображать не только числами, но и визуальным индикатором.

```kotlin
fun calculateProgressPercent(score: Int, requiredScore: Int): Int {
    if (requiredScore <= 0) return 0
    return ((score.toDouble() / requiredScore.toDouble()) * 100)
        .toInt()
        .coerceIn(0, 100)
}
```

Пример:

```text
Баллы: 72 / 100
Прогресс: 72%
Посещения: 9 / 12
Статус: в процессе
```

## 12. Рекомендации по интерфейсу

Интерфейс экрана физической культуры должен быть компактным и понятным.

Рекомендуемые элементы:

* карточка с текущим количеством баллов;
* индикатор прогресса;
* блок посещений;
* текстовый статус;
* подсказка, если студенту нужно добрать баллы или посещения.

Пример структуры экрана:

```text
Экран "Физическая культура"

[Карточка прогресса]
Баллы: 72 / 100
Прогресс: =======--- 72%

[Посещения]
9 из 12 занятий

[Статус]
До выполнения требований осталось 28 баллов
```

## 13. Обработка ошибок

При работе с университетскими сервисами возможны ошибки сети, авторизации или временная недоступность данных. Поэтому экран должен показывать понятные сообщения.

Примеры:

* «Не удалось загрузить данные. Проверьте подключение к интернету».
* «Требуется повторная авторизация».
* «Информация по физической культуре пока недоступна».

## 14. Модификация сверх базовой реализации

Базовая реализация экрана может просто показывать баллы и посещения. В качестве доработки можно добавить более полезную аналитику.

### 14.1. Подсказка по оставшемуся прогрессу

Экран может автоматически рассчитывать, сколько баллов или посещений осталось.

```kotlin
fun buildProgressHint(progress: PhysicalEducationProgress): String {
    val remainingScore = (progress.requiredScore - progress.score).coerceAtLeast(0)
    val remainingLessons = (progress.requiredLessons - progress.attendedLessons).coerceAtLeast(0)

    return when {
        remainingScore == 0 && remainingLessons == 0 ->
            "Требования по физической культуре выполнены"
        remainingScore > 0 && remainingLessons > 0 ->
            "Осталось набрать $remainingScore баллов и посетить $remainingLessons занятий"
        remainingScore > 0 ->
            "Осталось набрать $remainingScore баллов"
        else ->
            "Осталось посетить $remainingLessons занятий"
    }
}
```

### 14.2. Цветовой статус

Для быстрого восприятия можно использовать разные статусы:

| Статус | Условие | Цветовое значение |
| --- | --- | --- |
| Выполнено | Прогресс 100% | Зелёный |
| В процессе | Прогресс от 50% до 99% | Синий |
| Требует внимания | Прогресс ниже 50% | Красный или оранжевый |

## 15. Проверка результата

Для проверки экрана необходимо убедиться, что:

1. Данные корректно загружаются.
2. Ошибки отображаются понятным текстом.
3. Процент прогресса не выходит за пределы 0-100.
4. Интерфейс корректно выглядит на разных размерах экрана.
5. Подсказка по оставшемуся прогрессу соответствует данным.

## 16. Вывод

Экран физической культуры является важной частью приложения Eltech, потому что помогает студенту быстро оценить свой текущий прогресс. При правильной архитектуре экран можно развивать дальше: добавлять историю посещений, уведомления, детализацию баллов и интеграцию с общим профилем студента.
